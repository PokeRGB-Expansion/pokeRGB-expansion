# Box overflow as a build option

**Minimal and Core keep manual box selection. Developers can enable automatic placement on either preset or on Extended.** Suppose the party has six members, Box 1 has twenty and Box 2 is empty. Stock Red/Blue refuses a Master Ball before rolling for a catch and leaves the ball in the bag. With automatic placement the throw is legal and can secure the encounter. Especially in the Safari Zone, an extra trip to a PC cannot restore the same opportunity. This changes what the player can take home. [Stock capture and Safari checks](box-overflow-contract.md#what-a-stock-refusal-actually-costs)

The original US Red booklet devotes two headings on page 28 to selecting a box. It explains the refusal, shows the in-battle warning and instructs the player to change boxes at a Pokémon Center. The Route 3 trainer gives the same advice. Gold/Silver added direct PC transfers and retained the refusal. Memory limits help explain the implementation. The evidence shows that the published game taught players to manage the selected box. Keep that rule in the faithful presets and give developers a reliable way to replace it. ## Which code needs to change?

| Part | Shared code | Extra work when overflow is on |
|---|---|---|
| Choose a destination | Captures and PC-eligible gifts both check party and active-box space. Give those two callers a common way to request a destination when implementing the option. Keep each caller’s early refusals, success result and item or payment rules. | Search the remaining boxes in order, wrap once, and include earlier unsaved arrivals. Reserve space before reporting success. A failed throw releases its reservation. |
| Write the new member | Both paths already use the same boxed-arrival routine. Compute the member and its names once. Pass the chosen box and slot through naming, insertion and the confirmation message. Keep the preset’s choice of insertion order. | Hold the complete new member until a save can include it with the ball, Pokédex and event changes. The selected box stays selected. |
| Show counts | Reuse the active count in working memory and saved counts for initialized inactive boxes. First-use browsing must keep the prior adventure intact. | Include pending arrivals in counts. The existing twelve-count menu buffer overlaps other temporary data. A capture must use storage safe for battle and naming. |
| Save | Keep the compact format and the existing save boundaries for manual builds. The common fix for cancelling a box change can ship independently. | Compile in space for pending arrivals, save and recovery handling, and compatible format checks. Check the layout again for larger species IDs or other storage features. |

The ball and gift paths currently call the same writer at just two sites. Its name, trainer and record writes assume slot one of the live box. Even the routine whose comment describes taking a box number reads the selected box from memory. Refactor the actual inputs when the second destination needs them. Direct PC deposits, withdrawals, trades and the Day Care keep their own eligibility rules. This work needs a substantial change to remote storage and saving. It gives no reason to replace every preset’s storage layout first. ## Where pending arrivals must become permanent

Stock has four direct callers of the full save. The pause menu saves after confirmation. Entering the Cable Club saves before play. The Hall of Fame saves at the end of the adventure. A confirmed box change **copies the old box out and the new box in before calling the full save**. If the new box has pending arrivals, account for them when loading it. Also test saving an overflow catch before the first manual box change. A later first-use initialization must preserve the committed catch. [Pause menu](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/engine/menus/save.asm#L150-L166) · [Box change](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/engine/menus/save.asm#L358-L402) · [Cable Club entry](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/engine/link/cable_club_npc.asm#L55-L70) · [Hall of Fame](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/scripts/HallOfFame.asm#L42-L51)

A completed link trade calls a *partial* save. Four stock SameBoy 1.0.5 fixtures exercised the full and partial routines directly in English Red and Blue. Each began with a valid disposable save, then changed party HP, an owned Pokédex bit, money and the active box. All four saves reloaded. Both full saves kept all four new values. Both partial saves kept the new party HP and Pokédex bit, and restored the earlier money and active box. Neither routine alone changed the two banks that hold the twelve numbered boxes. Preserve this distinction when implementing overflow. These were save-routine tests, not linked trades or tests of overflow. [Full and partial save routines](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/engine/menus/save.asm#L246-L295) · [After-trade call](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/engine/link/cable_club.asm#L851-L866)

The [allocation experiment](box-overflow-contract.md) showed room on the stock cartridge for a compact record of each pending standard arrival. It established space only. Release the option once reset before saving restores the prior adventure, a completed save loads the whole new adventure, and an interrupted write either recovers a consistent state or is detected. Include manual box changes, both save types, fresh games over an existing save, earlier supported saves, exact destination names and full storage. Test the off build’s capture outcomes, save layout and memory use separately. [Existing cancellation repair and controls](box-picker-safety.md)

## How much of the search must be shared?

A disposable assembly experiment separated addressing a box from deciding whether another box is eligible. The stock address lookup loads the currently selected number and then looks up its location. Giving that second step a name added **zero instructions**. With the optional test routine left out, both complete ROMs matched their retail hashes byte for byte. An enabled, read-only search used 69 bytes of ROM in each build. It reused the address table and needed no new working-memory or save fields. [Original lookup](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/engine/menus/save.asm#L329-L356) · [Experimental source change](box-lookup-probe.asm)

The emulator checked every selected box in each color. The original lookup returned the same bank and address for all 24 cases. The search passed another 336 cases, including exactly one free destination in each possible position, several free destinations, all full, and a new adventure before box storage has been initialized. The test set the saved active-box count to zero while the live active box was full. It checked the returned box, every byte of battery storage, the selected box and the shared menu scratch space. The first-switch test used all twelve starting indexes for coverage; a stock new game starts in Box 1. [Recorded results](minimal-and-storage-checks.json)

The search assumes the caller has already found the party and live box full. It reads only saved counts or, before the first switch, treats other boxes as empty. A production search also has to count unsaved arrivals. No capture or gift calls this test routine. Selecting a box did not exercise writing a Pokémon, resetting, saving or recovery. The architectural conclusion is narrow: make the common lookup usable by both paths. The extra search and pending-arrival storage can stay in builds that enable automatic placement.

To repeat the experiment on a disposable checkout, add the label `LookupSavedBoxByIndex::` immediately before `and BOX_NUM_MASK` in `GetBoxSRAMLocation`. Append the supplied assembly file to the end of `engine/menus/save.asm`. Build English Red and Blue with RGBDS 1.0.4 in two clean checkouts. Use the default flags for the first. For the second, define `_READ_ONLY_BOX_PROBE` before the included test code. The JSON includes the four expected ROM hashes. The symbol file identifies the start and end of the optional routine.
