# What belongs in Core

## Release decision

[Minimal’s equivalence rule](minimal-action-review.md) now admits qualified field shortcuts. [Manual box policy](storage-policy-and-code.md) supersedes the earlier Core overflow default. Optional storage features have their own delivery gates.

The [current rule precedents](core-rule-precedents.md), [capture placement](box-overflow-contract.md) and [field controls](field-shortcut-contract.md) specify rules and options for the shared engine. The [Yellow review](yellow-rules-review.md) and [comparison of developer projects](developer-hack-comparison.md) add later field, text and Pokédex cases and specify where alternate learnsets or battle rules belong. The [developer library](tutorial-library.md) and [species-ID design](species-id-architecture.md) describe support across presets.

Use the combined accepted inventory for the complete Core. The checks below document stock battle failures, lost rewards and map-state repairs.

| Build | What to implement |
|---|---|
| Core | Apply the [existing battle and progression scopes](core-scope-review.md#core-battle-and-progression-repairs), the [accepted playthrough features](../docs/13-playthrough-intake.md), and the additional repairs below. Prioritize lost progress, freezes, wrong saved data and mistaken battle outcomes. |
| Minimal | Keep original gameplay, AI, rewards, probabilities and RNG rules. Include the type message and sound, Tower ghost disguise, Acid Armor redraw, and verified visual, text and sound corrections. A change to a seen bit, a reward, collision, an available command or a trainer's choices is a gameplay change. |
| Extended | Make modernization independently selectable. Keep ordinary Gen 1 behavior available to developers who choose only a graphics, editing or storage feature. Documented examples include later species/types, alternate AI, larger bag, MOVE POKÉMON, battle type and move information, and alternate battle formats. Double and triple battles are research directions. |

## Five stock battle findings

All 36 new cases used SameBoy 1.0.5 in original Game Boy mode with hash-checked English Red and Blue. Disposable parties, move sets, flags or HP were set in memory. The game then ran its own battle menu, move, trainer-scoring or award code. These are controlled tests of the stock game. Green inherits Blue's expected behavior and needs its own built-game checks. [Inputs, observations and ROM hashes](foundation-checks.json) · [Source records and hashes](evidence.md#e128)

To repeat the battle observations, start a disposable two-member party and enter a normal battle in each English version. The following values identify what each fixture controlled. The JSON gives every result, including the controls where each bug did not trigger.

| Fixture | Setup and observation |
|---|---|
| EXP. ALL (8) | Set both participant masks to 1 or 3, and put either zero items or one EXP. ALL in the bag. Set the enemy's base experience to 140, HP base stat to 120 and level to 21. Defeat it normally. Subtract each recipient’s pre-battle XP and HP stat experience from its final values. |
| Drain (8) | Give the actor 60 current HP and Mega Drain, with Splash on the other side. Compare a 200-HP doll with an inactive doll flag and the same stored doll HP. Capture the actor's HP, target's HP and doll HP after the turn. Swap actors. |
| Rest (8) | Seed poison, 70 current HP, and either a clear or set bad-poison flag. Use Rest and inspect the main status and separate flag immediately after the turn. Swap actors. |
| Transform swap (4) | Enter a wild battle, use Transform normally and verify its flag. Set the temporary moves to Tackle/Growl with 5/4 PP and the permanent ones to Transform/Splash with 9/20 PP. Open FIGHT, mark the first slot with SELECT, move down and press SELECT again. Repeat without Transform with identical temporary/permanent data. |
| Trainer scoring (8) | Enter a Sabrina-class trainer battle. Set the four enemy move IDs to 60, 105, 149, 115 or replace 149 with 60. Set the player's two type bytes to Psychic or Normal and clear its main status. Choose Splash. Read the four bytes in `wBuffer` when `AIEnemyTrainerChooseMoves.loopFindMinimumEntries` begins. Scores are move eligibility, before item or switch decisions. |

### EXP. ALL gives too little to a party with multiple participants

**Core should calculate the participants' share and the full party's share from independent copies of the original half award.** On a KO, the code halves the enemy's award data once and calls the award routine twice. That routine divides the same data in memory by the number of recipients. The second call therefore starts with values already divided for the first group. The same error affects stat experience, the hidden training points awarded from the defeated species' base stats. [Award caller](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/engine/battle/core.asm#L819-L857) · [Award routine](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/engine/battle/experience.asm#L294-L325)

The fixture used two healthy, untraded recipients, a level-21 wild opponent, base experience 140 and base HP 120. Each cell gives the two party members' gains in slot order. Both games agreed.

| Participants | Carrying EXP. ALL | Stock XP | Stock HP stat experience | Core target |
|---|---|---|---|---|
| One | No | 420 / 0 | 120 / 0 | Same |
| One | Yes | 315 / 105 | 90 / 30 | Same |
| Both | No | 210 / 210 | 60 / 60 | Same |
| Both | Yes | 156 / 156 | 45 / 45 | 210 / 210 XP and 60 / 60 HP stat experience |

Keep each half's original integer rounding and bonus order. Check one through six eligible recipients, fainted party members, all participants fainted, a trainer battle, traded Pokémon, the level cap and all five stat-experience values. The fixture establishes the double division. It does not determine a new rule for the separate fainted-recipient reports. Toss/sale protection remains its own requirement. [Recorded awards](foundation-checks.json) · [Shin Lite's three distinct EXP. ALL claims](https://github.com/jojobear13/shinpokered/blob/b35c2a536a1605841c8fb662aad18b0dbfd2a900/README.md#L330-L339)

### A Substitute should block the explicitly checked draining moves

The hit routine has failure branches for the drain and Dream Eater effects. A helper replaces the move effect with 0 or 1 before those comparisons. The earlier Japanese routine reads the effect again. In both English games, Mega Drain damaged the doll and healed the user on either side. With the doll removed the move hit the battler. **Core should make those effects fail against a doll, with no HP transferred and no damage to the doll.** Test Absorb, Mega Drain, Leech Life and Dream Eater, including awake/asleep controls and doll break thresholds. Only Mega Drain was played in this set. Preserve Swift's explicit early return, ordinary Substitute rules and the protected Toxic/Leech Seed interaction. [English hit routine](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/engine/battle/core.asm#L5228-L5263) · [Japanese comparison](https://github.com/Narishma-gb/pokegreen/blob/953f41b34108621b2bf13c3b1e53abfc9c3e5aec/engine/battle/core.asm#L5348-L5367)

### Rest leaves behind the badly-poisoned flag

Rest successfully put the user to sleep for two turns in all eight cases. When the badly-poisoned flag was set before Rest, it stayed set afterward, for either actor in both games. It stayed clear in controls. The residual-damage routine reads that flag separately from the user's main status. Researchers have also reported later escalating burn damage. The new fixture measured the stale flag itself. **Core should clear it on successful Rest.** Test a subsequent ordinary poison, burn, Toxic and Leech Seed, and a failed Rest. Preserve the shared damage progression while the user genuinely remains badly poisoned. Keep broader changes to burn/paralysis stat handling under their own rules. [Rest](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/engine/battle/move_effects/heal.asm#L23-L47) · [Residual damage](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/engine/battle/core.asm#L530-L597) · [Cartridge research](https://www.smogon.com/forums/threads/rby-recent-discoveries-resource.3541715/)

### Swapping copied moves changes the permanent party record

After Transform, SELECT swapped the two temporary moves and their PP. It also swapped the corresponding permanent slots, even when they contained entirely different moves and PP. Ordinary swaps correctly changed both records. **Core should allow the same action while transformed and write only to the temporary move set.** For example, swapping copied Tackle and Growl must leave the user's permanent Transform and Splash in their original slots with their original PP. Check the disabled slot, PP Up bits, active/benched state, battle exit and save/reload. The accepted cursor-position fix also applies to ordinary swaps. [Stock swap](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/engine/battle/core.asm#L2762-L2819) · [Observed before/after records](foundation-checks.json)

### Sabrina's Psywave counts itself as a better alternative

When scoring a resisted move, the AI looks through its own move list for a better choice. It includes the slot under review. A fixed-damage move qualifies as a better alternative before its type is checked. In a stock Sabrina-class battle with the moves Psybeam, Recover, Psywave and Reflect against a healthy Psychic type, the scores were 11, 10, 11 and 11. The lowest score is eligible, leaving only Recover. Against a Normal type all four scored 10. When a second Psybeam replaced Psywave, all four also scored 10 against the Psychic target. These were seeded move sets and turn conditions. They establish what that scorer does under those conditions. [Trainer scoring](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/engine/battle/trainer_ai.asm#L187-L252) · [Eight scoring traces](foundation-checks.json)

**Core should skip the slot being scored when looking for an alternative.** Psywave can still qualify as an alternative to Psybeam. A lone Psywave cannot disqualify itself. Check one move, duplicate IDs in distinct slots, a genuine second special-damage move, Fly, Super Fang, neutral targets and the normal trainer decision after scoring. Keep the existing neutral-value convention. CooltrainerF's unused chance comparison precedes both healing and switching. Restoring a return there would alter both choices, and the desired policy for each lacks the same evidence. Keep that behavior in Core. [Neutral-value investigation](evidence.md#e126) · [CooltrainerF routine](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/engine/battle/trainer_ai.asm#L344-L355)

## Damage, multi-turn moves and link play beyond the catalog

| Topic | Core decision and test boundary |
|---|---|
| Scaled Defense of zero (RGB-020) | Repair. Both damage paths divide large stats by four and pass only the low byte to damage calculation. Attack has a minimum of one. Defense can become zero when Attack exceeds 255 and Defense is 1–3. Crystal_ also published a cartridge demonstration of the freeze. Apply a minimum divisor of one in both paths. Check 255/256 Attack, 1–4 Defense, physical/special, critical hits and Explosion's separate halving rule. [Stock scaling](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/engine/battle/core.asm#L4103-L4133) · [Enemy path](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/engine/battle/core.asm#L4216-L4248) · [Crystal_'s demonstration](https://www.youtube.com/watch?v=V6iUlyS8GMU) |
| Reflect and Light Screen overflow (RGB-020) | Repair the wrap independently. With Defense 511, doubling and dividing by four gives 255. At 512 it gives 256, whose low byte is zero. At 513 it is still zero. Simply changing zero to one would make the screen catastrophically weaker. Preserve output throughout the representable range and calculate high values without wrap. Confirm expected damage using wide arithmetic and the original rounding on both sides. The precise treatment above the old limit is a project rule. ## Gift, map and engine decisions

**Audit result for the 47 direct scripted gifts.** Six call sites need a change or a safeguard. Three are the already accepted rooftop drink exchanges. The Route 1 clerk marks the free Potion as claimed before attempting delivery. Oak marks his five Poké Balls as claimed and prints success even if delivery fails. The Viridian clerk sets the parcel event regardless of delivery. Make each failed offer retryable, keep the original eligibility and verify one reward after a retry and save/reload. The Route 1 gift can be left until later. Ordinary access to a full bag for each of the two early Oak-related cases has not been demonstrated. The parcel safeguard also protects developers who change the starting inventory. The restored fossil stays pending if the party and box cannot accept it. Magikarp is paid for only on success. The Nugget Bridge reward remains available on refusal. Its mere presence does not establish that the caller handled payment or completion correctly. Hidden items, prizes, aides and ground pickups have separate handlers covered in the usability inventory. ### Donor claims that need narrower treatment

- **Safari bait and rocks.** Stock already draws a counter increment from 1 to 5. Its text routine decrements before the next player command and restores the species catch rate on expiry of anger only. Separate the stored increment, the number of future turns, the message and the lasting catch rate. Keep existing odds and timing in Core absent evidence of the intended neutral rate after bait. Correct demonstrably false feedback in Minimal if a turn-by-turn capture shows it. Set up each counter at 1 and 2 with the other zero and record the rate, message and flee check before each action. [Item code](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/engine/items/item_effects.asm#L1432-L1482) · [Turn-end code](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/engine/battle/safari_zone.asm#L1-L27)
- **An inaccessible hidden Nugget.** Two stock tables place it at (10,1) inside the Safari gate. The map is only four blocks wide, or eight standing squares. That establishes a data mismatch. It supplies no intended replacement tile or evidence the reward was meant to ship. Keep the stock economy. A developer can place the Nugget deliberately, update both tables and test its one-time collection. This differs from paying 20 for an existing reachable reward encoded as 40. [Hidden event](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/data/events/hidden_events.asm#L411-L413) · [Itemfinder entry](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/data/events/hidden_item_coords.asm#L24) · [Map dimensions](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/constants/map_constants.asm#L248)

## Evidence and release gates

The working evidence comes from the linked English ROM disassembly, published comparisons with Japanese Red/Green and English Yellow, the 36 controlled stock cases, linked ROM tables, developer feature lists, first-hand cartridge research and the earlier manuals and remake review. The disassembly reproduces the English ROM bytes. Comments and labels were added during reverse engineering. A broken branch, an unreachable return value or two halves of the engine disagreeing can justify a repair without proving what an individual developer thought. A later design change or a donor calling something a bug carries less weight. [Historical evidence](historical-evidence.md) · [Comparison sources](donor-review.md)

The review also searched assembly comments for “bug”, “bugged”, “buggy” and “glitch” in audio, data, engine, home and scripts at the pinned revision. The 50 matching lines include duplicates, tentative annotations, inactive code and deliberately preserved rules. That pass surfaced the bench table, door sound, unused Card Key route and serial clock case. Neither that search nor the archived list exhausts possible defects in every script or interaction.

The [table checker](../tools/check_foundation_tables.py) reads a built checkout’s stock Red and Blue ROMs, symbols and Tower map assets. Run `python3 tools/check_foundation_tables.py /path/to/pokered` to verify the recorded coordinates, terrain, bench table, sprite addresses and slot-selector model.
