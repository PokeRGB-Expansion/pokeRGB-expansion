# Decisions on the 94 archived bug reports

The archived pret catalog lists proposed changes from contributors. Each row below gives the project's current placement, the reason and the test required for that particular scope. The numbered source link opens the relevant stock code at the implementation revision. The [catalog index](bug-catalog.csv) gives the original report and its exact lines in the archived revision. The delivery column records when the accepted part reaches the source tree. Each required check still applies. A code citation identifies the path reviewed. Conditional reports still need the stock reproduction specified in their row.

The complete accepted Core scope is the public release target. The placements below describe what belongs in each build.

| Placement | Meaning |
|---|---|
| Minimal | Include the change in both Minimal and Core. Preserve team strength, timing of opportunities, costs, intended preparation and meaningful choices. Compare equivalent actions under the same gameplay rolls. |
| Core | Include the change in Core. Minimal retains the corresponding stock outcome. Extended inherits Core unless the author chooses an alternative. |
| Shared engine | Use one corrected implementation in every preset. In these cases the change preserves the relevant stock results and removes a data or code defect. |
| Shared safety | Protect supported saves or resources in every preset. Report exactly which outcomes have been reproduced. Recovery promises require separate tests. |
| Author support | Make the capability available to an author who needs it, regardless of the selected battle rules. Test custom data separately from stock gameplay. |
| Keep / Hold / Split | Keep means retain the stock choice. Keep / link also requires agreement between supported peers. Hold means keep it out pending the evidence stated in the row. A split row gives the separate calls for its parts. |

The placements for the 94 entries total 21 Minimal, 27 Core, four shared engine, two shared safety, three author support, 21 keep, one keep/link, eleven hold and four split. Counts describe reports. A split report contains more than one decision.

Every row was reviewed under [Minimal’s equivalent-action rule](minimal-action-review.md). A source finding, an unconfirmed report, and a passing prototype have different evidence requirements. Each row names the condition to test before an implementation ships. [Investigation methods](foundation-audit.md)

## Evidence from the full-preset review

**Sign and map events.** The Route 16 sign stands at (5,17). Its three adjacent squares on Route 16 and the square at (5,0) on Route 17 are all passable. In hash-checked Red and Blue, the stock sign routine returned the route text ID from the three Route 16 sides and found no sign when facing it from Route 17. A prototype added an entry on Route 17 for the shared border and pointed its text script at the same string. Both colors then found the correct text from all four sides. Facing away still found no sign. These routine tests used each built map’s actual event records. They did not measure a complete bicycle ride. The Tower check used the stock and corrected coordinate readers, two real triggers, two impassable coordinates and two staircase controls. [Border data](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/data/maps/headers/Route17.asm#L1-L4) · [Sign text](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/text/Route16.asm) · [Tower terrain review](foundation-audit.md#gift-map-and-engine-decisions)

**Itemfinder and collision checks.** The Itemfinder review read all 54 hidden-item records from each retail ROM. For each record, it compared the original and corrected comparisons at every player position inside that map’s dimensions. The 64,160 comparisons per color agreed, including assigned coordinates for the inaccessible gate item and the unused map. Separate routine checks tried a synthetic item on each zero axis, range endpoints and claimed items. For the land and water collision tables, a model compared the retail parser’s exact pointer steps with a bounded three-byte record scan for both colors, 24 tilesets, and all 256 × 256 ordered tile-byte values. All 6,291,456 carry results matched. The stock parser could read as far as 299 bytes past the land terminator and 236 past the water terminator. Eight representative calls per build exercised actual machine code. Cycle timing, all map transitions and downstream edited tables require their own checks. [Hidden-item coordinates](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/data/events/hidden_item_coords.asm) · [Collision routine](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/home/overworld.asm#L1297-L1344)

**Independent new adventures.** Eight stock/prototype New Game runs used a valid disposable previous save with the forced-bike flag clear or set, in both colors. The flag-set fixture also identified the previous map as Route 17. Each run loaded the save through the main menu, chose New Game and reached the starting bedroom walking. Only the stock builds retained a set flag from the old adventure. Clearing this bit during new-game initialization preserved the prior save bytes, normal controls and the separation between adventures. The field-use code separately reads the bit when checking Surf. The fixture measured initialization; it did not play a new game all the way to Surf. [Initialization](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/engine/movie/oak_speech/oak_speech.asm#L1-L26) · [Surf restriction](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/engine/overworld/field_move_messages.asm#L21-L50)


**Graphics transfer limits.** Eight additional SameBoy 1.0.5 fixtures ran the actual stock and prototype tile loaders in Red and Blue. The stock slot routine copied all 384 bytes of the reel asset and 64 bytes of neighboring data into each of two destinations. The healing routine copied all 32 graphic bytes and 16 bytes of neighboring sprite data. In both prototypes all asset bytes matched, and a marker placed after each destination stayed intact. This verifies the copy boundaries. A different healing blink, improved image quality and unchanged reel timing still require independent visual or gameplay evidence.
