# The first CHANGE BOX can alter an older save on cancellation

**Minimal and Core should preserve the last saved adventure when a player backs out of the box chooser.** Also show the occupancy of the highlighted box in the existing chooser. One is a save-data repair. The other gives a useful view of information the menu already reads. Both work with manual storage and the original PC interface.

## Confirmed stock behavior

The problem needs two adventures. The older saved game has Pokémon in inactive boxes. Start New Game and leave the new adventure unsaved. In its first CHANGE BOX, answer Yes to the notice that changing boxes saves, then press B at the list without choosing a box. In the stock games, the old main save remains valid and the older party still loads, but inactive boxes can now appear empty. The initial Yes authorizes saving **when a box changes**. At this point none has changed. [Stock prompt](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/data/text/text_3.asm#L22-L33) · [Stock change flow](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/engine/menus/save.asm#L358-L402)

The new adventure has its own first-change flag. The stock code uses that flag to empty all twelve battery-backed box headers **before** displaying the chooser. It also recomputes their checksums. B then returns without saving the current adventure. The older inactive boxes are marked empty even though their entire record payloads were not erased. The older active box is also stored with the main save and follows a different load path. The player’s PC exists before meeting Bill and can be labeled SOMEONE’s PC. ### What ran

SameBoy 1.0.5 ran the English Red and Blue retail ROMs and a separate experimental build of each color. A disposable save had a two-member party, Box 1 selected and one identified member each in Boxes 2 and 8. The main save and box checksums were valid. The stock main menu recognized the save and offered CONTINUE. The fixture selected NEW GAME through that menu, supplied a legal test party and one live Box 1 member, and invoked the real CHANGE BOX screen. Its Yes, No, B and box selections ran through the game’s input handling. Each branch started with a fresh copy of the same disposable save. The test loaded the resulting save through the game and queried its box counts. This exercises the menu and persistence path without playing a route to the Pokémon Center. [Fixture outcomes](core-refinement-checks.json)

| Input in unsaved new adventure | Stock Red and Blue | Experimental Red and Blue |
|---|---|---|
| Decline the save notice | All battery bytes identical. The older party and both inactive box members remain available. | Same |
| Accept the notice, open the list, press B | Battery banks 2 and 3 changed. The older party loaded. Both previously occupied inactive boxes read as empty. | All battery bytes identical. The older party and both inactive box members remained available. |
| Accept the notice and select Box 2 | The new adventure saved with Box 2 selected. Its prior live Box 1 member was stored in Box 1. | Same |

The prototype made two local changes. It defers initializing the new adventure’s battery box banks until an actual box selection. While the first change is pending, it builds the selector’s counts from empty inactive boxes and the live active count. This prevents exposing a previous trainer’s boxes or showing uninitialized counts. This is a tested repair for this sequence. Interrupted-save recovery and automatic capture storage have separate requirements. [Related storage contract](box-overflow-contract.md)

## A useful display change for both presets

The stock chooser already collects the numeric counts of **all twelve boxes**. It replaces the active box’s saved count with its live working-memory count. The renderer then reduces each count to a single distinction. An empty box has no ball icon, and boxes containing 1, 19 or 20 Pokémon all have the same icon. Two additional stock fixtures, one per color, loaded those values across the box banks. Both read 7 from the live active box despite its saved header reading 0. The numeric readings differed while every nonempty row got the same icon. [Count collection](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/engine/menus/save.asm#L575-L617) · [Menu rendering](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/engine/menus/save.asm#L487-L506)

Show the selected row’s occupied and total places, such as **19/20** or **20/20**, in the existing screen. The selected row can differ from the active box. Refresh the count as the cursor moves. Keep legal full boxes selectable for browsing or withdrawal. Reading an initialized count must never trigger a save, reserve a slot, or change the active box. This helps both Minimal and Core players choose a box before leaving town. Test Boxes 1 and 12, multiple nonempty boxes, a full box, the first visit with an older save present, A and B, and each supported capacity. Only the count-reading behavior and the cancellation repair were exercised here. The numeric display is a planned UI change.
