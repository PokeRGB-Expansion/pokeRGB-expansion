# A shared library for hack developers

Minimal, Core and Extended are named, tested build presets in one repository. Start with a preset, then choose the changes a particular game needs. A developer can start with Core, keep Charizard’s Fly permission, restore the original Ghost matchup and set custom trainer moves independently. The build produces one game with those rules.

## What developers should configure

The [paired-edition example](emerald-rogue-builds.md) shows how two public versions can use the same adventure and one Special stat while selecting different species and rules.

| Kind of choice | How it should work | Example |
|---|---|---|
| Original behavior and a supported correction | Give the shared implementation a named rule where two presets need different behavior. Group coupled fixes according to their game rule. | Minimal keeps stock Focus Energy. Core and Extended use the corrected calculation. |
| A single data edit | Expose an ordinary, named data entry with validation. A developer can make the edit directly. Common groups of edits can have a reusable data file. | Add Fly to Charizard’s HM list alone, or select the whole Yellow machine-compatibility table. |
| Independently useful engine capability | Enable it at build time and compile its data and code when used. Clearly state its costs, dependencies and effect on the game. | A move relearner, an EXP bar, two-byte species IDs, or the move-based physical/special split. |
| Authoring and debugging | Provide easy-to-edit tables, checked references, small examples and diagnostics. Use the normal game entry points in tests. | A custom trainer party with one explicit move override. Keep the trainer’s decision rules and other generated moves. |
| Story, difficulty and assets | Supply examples or data choices. The hack author owns the content. | A rival speech, rematch team, gym music or a different roster. The community library need not define a global switch for every NPC. |

**Configuration order.** Select a color, then a preset for its default rules, then the project's named feature choices and data overrides. If a pack supplies Yellow’s eight TM/HM differences and the author changes one species afterward, the explicit species edit wins. Reject competing packs that set the same field at the same priority unless the author resolves the conflict. Show the resolved settings, content list and relevant format versions in the build output. Keep different configurations’ intermediate files separate. A save or multiplayer compatibility claim depends on the actual format, content IDs and rules selected. A preset name alone cannot establish it.

**Supported combinations.** Test the reference presets and each supported option on and off. Add focused combination tests where options share state, data or controls. An untested custom combination should be identifiable. An Extended reference build should ship only with an explicit, versioned list of selections. Its first example can demonstrate type information and the move-reference panel on a 151-species game with one Special stat. A second example should enable a wide species roster while retaining single battles and the original type chart. Both examples are planned. The choice of which example to advertise first can wait for working features. [Feature contract](../docs/14-features-and-extensions.md) · [Capacity design](species-id-architecture.md)

## What the pret tutorial index actually asks developers to do

The linked inventory assigns a project placement to **all 108 subject links** in the wiki's feature, editing and debug sections. It also records the eight concrete topics and one general request in the wiki’s to-do list. Navigation, five assembly learning resources and the three links to other indexes are excluded from that count. Each linked subject was matched to a file at wiki revision `e11cd15f002f1387a52c086bd7c36038a5b0ca14`. The CSV records the page name at that revision, its index line and the live URL. A listed tutorial establishes that someone documented the need. It cannot establish how many developers want it, whether its instructions still fit the current source, or whether it belongs in the default game. The original request for authoring tutorials specifically describes the burden of scattered tables and hidden special cases. [Coverage inventory](tutorial-coverage.csv) · [Pinned tutorial index](https://github.com/pret/pokered/wiki/Tutorials/e11cd15f002f1387a52c086bd7c36038a5b0ca14) · [Upstream authoring discussion](https://github.com/pret/pokered/issues/278)

The inventory’s **Author** rows describe clean ways to edit or extend a game. **Core** refers to an already scoped default repair or feature. **Option** and **Content** identify reusable alternatives and author-owned data. **Capacity** and **Engineering** describe implementation work whose value depends on a real consumer. **Boundary** requires a demonstrated supported path. **Tool** is developer-only. The combined entry separates a stock EXP. ALL correction from optional presentation changes. A request without a published implementation stays labeled as such.

### What to build first for developers

1. **One custom trainer and one ordinary encounter edit.** Demonstrate adding a trainer with stock-generated moves, then override one member’s moves in data. Show that the generated stock parties, rival starter-dependent moves, Gym Leader signature moves, rewards and AI choices still match. A map edit should accept a species by name and catch invalid references before producing a ROM. These examples save authors work even if they keep all 151 original species. [Special move data](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/data/trainers/special_moves.asm) · [Upstream trainer authoring request](https://github.com/pret/pokered/issues/278)
2. **One species or move end to end.** Document or generate the necessary linked tables. Verify that the Pokémon can be encountered, caught, stored, saved and retrieved, and that the move can be learned, displayed and used. Keep starter selection and lab previews linked to the same species definition. Test a synthetic custom learnset with two moves at one level as well as a battle that crosses two levels. Those two cases reach different defects or limitations. [Species tutorial](https://github.com/pret/pokered/wiki/Adding-a-New-Pokemon) · [Level-up routines](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/engine/pokemon/evos_moves.asm#L323-L386)
3. **Deliver useful shared UI once.** Quantity steps of ten, contextual HMs and cursor restoration already have Core contracts. Optional EXP bars, extra stats pages and battle type indicators should share the display code and define who owns each screen area. Combined options must fit the original screen and preserve the ghost disguise. The wiki's B-button example moves the cursor to Run. Actually attempting an escape changes the input contract and must be a separate choice. [Contextual HMs](https://github.com/pret/pokered/wiki/Use-Cut,-Surf,-and-Strength-From-the-Overworld) · [Escape shortcut](https://github.com/pret/pokered/wiki/Push-B-in-wild-battle-moves-to-Run) · [Battle information](../docs/15-battle-information.md)
4. **Make shared limits explicit before expanding them.** A tutorial for a new damaging move with an accuracy-lowering effect exposes an existing assumption that some effects belong only to status moves. A separate effect dispatch routine doubles the effect index in an eight-bit register after subtracting one. Effect ID 128 still addresses the last distinct entry, whereas 129 wraps onto the first entry. Test 127, 128 and 129 if expanding the effect table. The move ID, effect ID, animation ID and species ID each have their own capacity. [Custom move example](https://github.com/pret/pokered/wiki/Check-base-power-before-skipping-damage-calculation) · [Stock effect dispatch](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/engine/battle/effects.asm#L6-L21)
5. **Verify interacting changes with real builds.** Combine the optional 64-slot bag with sorting and PC transfer, and test full capacity, duplicate stacks and cursor position. Combine wide species IDs with classic move types and ordinary trainer AI. Combine Gen 2 move typings with unified Special, then separately with move-based physical/special categories. Publish how to build each supported example. Document the behavior when the options are disabled. [Bag design](bag-memory.md) · [Test plan](../docs/07-testing-ci.md)

Pokéemerald Expansion supplies a working example of selectable species families and rule settings, including real limits on what its stock configuration can reproduce. That is evidence for a shared library and explicit defaults. Its adoption percentage across all Emerald hacks has no reliable denominator in these sources. For PokéRGB, count independent downstream projects that successfully build, customize and update the base. A successful first customization is a better release test than a long list of switches.
