# Which changes need shared engine work?

A preset selects the rules for a build. Share the code that two callers need to perform the same action correctly. Keep extra storage and new behavior behind the feature that needs them. The amount of code a feature touches and its effect on game balance are separate decisions.

The source links below use the [pinned English Red/Blue revision](https://github.com/pret/pokered/tree/ba9c0568f64ae602fadda577a08c66639f93082a). The implementation boundaries are proposed. The local battle edits described below can use the stock party, box and save formats. Storage features have separate requirements.

## Actions with more than one way in

**Field HMs.** Keep the party command. Add an overworld caller for an eligible tree, shore or pushable boulder. The stock party menu chooses the Pokémon, checks its badge, calls the move and decides which menu to show next. The overworld checks hidden events, objects, signs and trainer state. Share the move, badge and target checks where both callers need them. Let each caller handle its own prompt, cancellation and return screen. A failed shortcut must leave normal interaction available. No new saved field is needed for these three prompts. [Party dispatch](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/engine/menus/start_sub_menus.asm#L104-L128) · [Move checks and returns](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/engine/menus/start_sub_menus.asm#L152-L191) · [Overworld input](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/home/overworld.asm#L74-L108) · [Field fixtures](field-shortcut-contract.md)

**Registered items.** A SELECT shortcut must check the item is still in the bag and apply the same restrictions as the bag command. The Bicycle has a forced-riding check in the **menu**, separate from the item routine. A call to the item routine alone misses that check. Store the registered item’s ID so reordering the bag keeps the choice. Reserve a defined saved location and treat old saves as having no registered item. Verify the existing SELECT functions in lists and battles. [Bag-side check](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/engine/menus/start_sub_menus.asm#L361-L399) · [Bicycle handler](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/engine/items/item_effects.asm#L638-L667)

**Menus and screens.** Apply the capacity check on the requested withdrawal. Browsing and STATS only need a valid list. Keep row and scroll state with the caller that owns the list. Removing an item currently resets both, while the item PC also resets them in its own code. Fixing one reset cannot cover both. Battle move reordering has its own cursor and writes to both party and battle moves. Test the cursor repair separately from the rule for swapping temporary moves after Transform. These changes need coordinated callers and temporary state. They need no new box format. [Withdrawal](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/engine/pokemon/bills_pc.asm#L256-L287) · [Shared item removal](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/engine/items/inventory.asm#L121-L145) · [Item PC](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/engine/menus/players_pc.asm#L72-L93) · [Battle move swap](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/engine/battle/core.asm#L2762-L2812)

**Move learning.** The level-up reader chooses an eligible move. A second routine fills an empty slot or asks which move to forget and sets the new move’s PP. Reuse that second routine for an optional relearner. Give the service its own eligibility, access and cost rules. An always-available tutor changes which four moves a player can prepare at a particular point in the adventure. The Core skipped-level repair only needs to check moves earned at the levels actually crossed. [Level-up lookup](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/engine/pokemon/evos_moves.asm#L323-L377) · [Teaching and replacement](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/engine/pokemon/learn_move.asm#L11-L63)

**Other presentation and map changes.** Use the existing screen or map owner for quantity steps, shop returns, elevator selection, trainer sight, grass recognition and Acid Armor’s final redraw. A visible change can still have shared callers. Compare the other quantity menus, trainers, shores and sprite states when touching a shared routine. TM names and reference pages should read the configured move data. Battle overlays need room on the screen, a way to return to the move menu and a rule for disguised opponents. They can ship independently of new battle rules and species formats. ## Changes that cross storage boundaries

| Feature | Shared work | Work specific to the feature |
|---|---|---|
| Stable box order | Captures and PC-eligible gifts both call `SendNewMonToBox`. Make the destination slot explicit. Write the species list, record, original trainer name and nickname at that same slot, and use it in the confirmation text. | Appending inside the selected box requires no new save format. The existing party deposit already appends and copies the departing Pokémon’s data. Preserve the separate construction of a fresh catch or gift. [Gift caller](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/engine/events/give_pokemon.asm#L7-L39) · [Capture and message](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/engine/items/item_effects.asm#L551-L579) · [Record insertion](cursor-box-and-trainers.md) |
| Box overflow and MOVE POKÉMON | Describe a destination by box and slot. Preserve complete records. Keep the existing PC’s read-only view of box counts safe on cancellation. | Overflow needs a capacity decision before throwing a Ball and durable handling of unsaved arrivals outside the selected box. MOVE needs an interface that transfers existing members and also handles refusal, cancellation and the last party member. These are independent features. The stock box-change operation saves the entire adventure. [Stock save path](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/engine/menus/save.asm#L358-L402) · [Storage gates](box-overflow-contract.md) · [Picker tests](box-picker-safety.md) |
| Larger bag | Use the configured live bag label in inventory, shop, PC and battle callers. The shared item insertion routine selects the bag limit by comparing its address with that label. | The 64-slot option needs its own 134-byte reserve, initialization after the progress-data clear and a tested save import. The compact build keeps the 20-slot bag and its original field addresses. The allocation test establishes fit. Transactions, reload and feature combinations still need execution tests. [Bag/PC limit selection](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/engine/items/inventory.asm#L7-L29) · [New-game order](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/engine/movie/oak_speech/init_player_data.asm#L15-L46) · [Measured allocation](bag-memory.md) |
| Wider species IDs | Give authors one way to reference a species and explicitly select how a record stores it. Keep move IDs and types separate from species IDs. | The wider option changes party and box records, the Pokédex, saved data and cable packets. A compiled Gen 1 example grows the whole party from 404 to 417 bytes. Ship the compact format first and verify high IDs through all four systems before promising wide-roster support. [Measurements and link boundary](species-id-architecture.md) |

For the bag review, a scan of the pinned assembly under `engine/`, `home/` and `scripts/` found **25 instruction or data lines in 13 files** that name `wNumBagItems` or `wBagItems` outside a comment. This identifies callers to check when moving the bag. Bulk save copies and code that receives a pointer indirectly also need tests. The count does not measure how many files need edits.

A shared refactor is ready when the original configuration still passes its behavior, memory-layout and save checks, and the new caller or feature passes its own cases. For changes that affect both players in a link battle, check both ends before publishing a compatibility claim. [Preset and compatibility tests](../docs/07-testing-ci.md)
