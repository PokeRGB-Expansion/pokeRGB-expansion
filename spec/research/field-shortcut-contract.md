# Field shortcuts in the three presets

[Stock field observations](core-refinement-checks.json) record successful use and refusal cases. D54 sets the defaults; the checks below define what an author must preserve.

**Minimal and Core both offer A-button Cut, Surf and Strength when the party can already use that move at the target.** Extended inherits the same behavior. Keep the existing party commands. [Minimal placement](minimal-action-review.md) · [Field move requirements](../docs/13-playthrough-intake.md#pn-004)

Cutting a tree through the party menu and confirming Cut at that tree should have the same effect. The original Red booklet explains that Cut removes a tree and Surf crosses water. A prompt can remind a qualified player of that connection. Leave existing NPCs, signs and puzzle interactions accessible, and offer nothing when the party cannot perform the action. [US Red booklet, p. 28](https://www.videogamemanual.com/gameboy/Pokemon%20-%20Red%20Version%20%28USA%29.pdf#page=30)

## A refused Surf dismount closes the wrong menu

**Minimal and Core should return to the party list after a refused manual Surf dismount** when the player has spent no move, step or turn. Compare the next legal action and map state. This menu return and the shore shortcut have separate tests.

The shared item handler initializes its result to success. A failed attempt to board calls the failure routine, which clears that result. A failed attempt to get off prints the refusal directly and leaves the result set. The party handler treats that refusal as a success and closes the menus. Return the existing dismount refusal text through the failure path. Keep the player in place, preserve the Surf state, and leave successful boarding, successful landing and automatic walking dismount alone. **Eight stock field-menu fixtures.** SameBoy 1.0.5 in DMG-B mode ran four fixtures per English retail ROM. After New Game, the fixture supplied a disposable Vaporeon with Surf and a healthy Staryu, an empty bag and a scripted warp to Pallet Town. Walking, terrain checks and party commands then ran normally. Coordinates below are (x,y).

| Setup in each color | Observed result |
|---|---|
| Healthy Vaporeon, 15 PP, Soul Badge | From (5,13) facing south, Surf boarded at (5,14). Using Surf again facing water tile 0x14 refused to land. The result byte was 1, the character remained at (5,14) in Surf state 2, and START opened the main menu from the map. Walking north returned to (5,13) on foot. PP stayed at 15. |
| Fainted Vaporeon, 0 PP, Soul Badge | The same board, refusal, menu exit and normal walking dismount occurred. PP stayed at zero. This is a protection test for the new shortcut. |
| Healthy user, no Soul Badge, valid shore | The character stayed on foot at (5,13) and returned to the party list. Selecting Staryu then opened Staryu's action menu. |
| Healthy user, Soul Badge, no water ahead | At (5,12) boarding failed, the result was zero, the character remained on foot and Staryu could be selected in the party list. |

The ROM SHA-1 values were `ea9bcae617fdf159b045185467ae58b2e4a48b9a` (Red) and `d7037c83e1ae5b39bde3c30787637ba1d4c48ce2` (Blue). A release test should also refuse a blocked shoreline or occupied exit tile and retain the selected Pokémon. These fixtures exercised the original games. ## Dispatch and acceptance

1. Allow the normal overworld to process warps, battles, controlled movement and higher-priority interactions first. Hidden items, bookshelves, Card Key doors, signs and NPCs must still work. Put Strength in the recognized boulder interaction. For terrain prompts, recompute facing and standing tiles only after other interactions have declined the action. Prompt on an unclaimed, eligible water surface. Avoid advertising Surf on decorative objects merely because their tile shares a water ID. Preserve existing manual interactions with those objects. [Original input order](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/home/overworld.asm#L54-L108) · [Facing tile selection](https://github.com/pret/pokered/blob/ba9c0568f64ae602fadda577a08c66639f93082a/engine/overworld/player_state.asm#L257-L295)
2. On No or B, return control without changing position, facing, party order, move PP, map blocks, Strength state, travel mode, step counters or event flags. Handle one new A press once. An A held through the message must not retrigger the prompt or accept it automatically. Explicit user confirmation is required.
3. On Yes, run the same validated operation as the party command. Confirm identity, action and map state using the ordinary code path. Compare manual and shortcut results for two qualifying users, an eligible fainted user, zero PP, an HM taught by trade, missing badge, already-active Strength, ordinary shores, blocked water-tile pairs, both Seafoam boulder flags and forced cycling. On a water encounter square, the successful board should have the normal step and encounter behavior. Pressing A or declining the prompt must not make an extra encounter roll. Compare equivalent actions with controlled rolls. Different menu times can change real timer samples. Also test hidden objects, signs, moving NPCs and trainer sight on a custom map where their targets touch.
4. Keep the precedent precise. Gold/Silver checks party move, badge, water and direction before offering Surf. FireRed’s trees and boulders have their own scripts. Yellow Legacy 1.0.10 checks a tree and displays an explanation before it checks the party or badge. This demonstrates a meaningful design choice about hints. Our Core contract preserves stock feedback when the shortcut is unavailable.
