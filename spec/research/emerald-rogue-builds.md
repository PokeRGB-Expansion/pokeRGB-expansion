# Two editions of the same hack

**A PokéRGB author should be able to maintain one adventure and publish two editions from the same revision.** Pokémon Emerald Rogue provides a working example of the player-facing result. Its author calls the editions **Vanilla** and **Expanded (EX)**. Both offer the Rogue adventure. Vanilla uses Emerald-style battles with Rogue’s own changes, including altered evolution methods. EX adds later Pokémon and battle features such as Fairy and move-based physical/special categories. [Author’s edition descriptions](https://www.pokecommunity.com/threads/pokemon-emerald-rogue.479406/)

## What the source and release records show

- Pokabbie’s public GitHub release history listed **six version pairs** on November 23, 2026: 1.0, 1.1, 1.2, 1.3, 2.0 and 2.1. Each pair has separate source tags. The author directs players to Hackdex for downloads. The live Hackdex file list could not be independently verified during this review. The six pairs establish the publishing pattern. The checked Vanilla branch displays v2.2.1a and the EX branch displays v2.2.1, so a maintenance suffix can differ in source. [GitHub release history](https://api.github.com/repos/Pokabbie/pokeemerald-rogue/releases?per_page=100) · [Hackdex listing](https://www.hackdex.app/hack/emerald-rogue) · [Vanilla version string](https://github.com/Pokabbie/pokeemerald-rogue/blob/5ccb74cf1ef2c0349dfa5d70883b030bbc9ff803/src/data/rogue_strings.h#L3-L12) · [EX version string](https://github.com/Pokabbie/pokeemerald-rogue/blob/a6adfcf18d7eaf99c2803e4b0bc04eca7af2f014/src/data/rogue_strings.h#L3-L12)
- In the paired **v2.1** source tags, Vanilla’s National Pokédex ends at **386, Deoxys**. EX enables Generations 1–9 and its National Pokédex ends at **1,025, Pecharunt**. These counts describe numbered species in the build. The selected roster and encounter rules still determine what a player can find on a run. [Vanilla Pokédex](https://github.com/Pokabbie/pokeemerald-rogue/blob/c33212ebcda821d78aa8d9b69a5e06c6995c212b/include/constants/pokedex.h#L391-L426) · [EX generation settings](https://github.com/Pokabbie/pokeemerald-rogue/blob/559792325f500d480b892799218ee015962f93a2/include/config/species_enabled.h#L9-L20) · [EX Pokédex](https://github.com/Pokabbie/pokeemerald-rogue/blob/559792325f500d480b892799218ee015962f93a2/include/constants/pokedex.h#L1037-L1052)
- Vanilla chooses the attacking stat from the **move’s type**. EX enables the later category rule and normally reads the category on the **individual move**. For example, Bite’s EX entry explicitly selects physical damage. The version tags use different source trees and Makefile defaults. They still share the exact same adventure-path generator and hub-entrance script, verified by comparing the Git file contents. [Vanilla damage path](https://github.com/Pokabbie/pokeemerald-rogue/blob/c33212ebcda821d78aa8d9b69a5e06c6995c212b/src/pokemon.c#L3401-L3417) · [EX rule setting](https://github.com/Pokabbie/pokeemerald-rogue/blob/559792325f500d480b892799218ee015962f93a2/include/config/battle.h#L63-L70) · [EX category lookup](https://github.com/Pokabbie/pokeemerald-rogue/blob/559792325f500d480b892799218ee015962f93a2/src/battle_util.c#L11239-L11255) · [Bite](https://github.com/Pokabbie/pokeemerald-rogue/blob/559792325f500d480b892799218ee015962f93a2/src/data/battle_moves.h#L762-L775) · [Vanilla Makefile](https://github.com/Pokabbie/pokeemerald-rogue/blob/c33212ebcda821d78aa8d9b69a5e06c6995c212b/Makefile#L1-L6) · [EX Makefile](https://github.com/Pokabbie/pokeemerald-rogue/blob/559792325f500d480b892799218ee015962f93a2/Makefile#L1-L6) · [Shared path generator](https://github.com/Pokabbie/pokeemerald-rogue/blob/c33212ebcda821d78aa8d9b69a5e06c6995c212b/src/rogue_adventurepaths.c#L154-L185)

The same trainer role can have different data. Emerald Rogue gives Kate the ace entry Gastly in Vanilla and Tarountula in EX. Both editions can refer to Kate’s ace by the same name. This is a concrete pattern for authors who want the same trainer encounter in both releases. ## A downstream release test for PokéRGB

Use a hypothetical **Yellow Rogue** as the worked example. Its author supplies the Yellow-themed adventure on the English Red/Blue foundation. These are proposed project choices for testing the foundation.

| Choice | Yellow Rogue Vanilla | Yellow Rogue EX |
|---|---|---|
| Base preset | Core, or Minimal if the author wants its stock battle outcomes | Extended, inheriting Core |
| Pokémon | Original 151, using the compact species format | A larger roster once wide IDs and its content are tested |
| Special stat | One Special | One Special, including an explicit base Special value for every added species |
| Battle rules | Rules of the chosen base | Select individual additions, such as Fairy or damage category per move |
| Adventure | Same maps, room logic, rewards and progression scripts | Same files. Named encounter or trainer tables supply any edition-specific opponents. |

Check in the two build settings beside the shared content. Give each clean build its own output directory. From a single tagged revision, build and apply both patches to the stated base, check their output hashes, and play the same short route through a battle, reward and save/reload. Exercise one deliberately different encounter in EX and verify that Vanilla’s tables contain only its allowed species. Catch and reload an above-255 species in the wide build. Verify that a special attack and an incoming special hit both use the single Special stat in each edition. These checks test the capabilities an author actually needs to ship the pair. [Preset settings](tutorial-library.md) · [Wide species IDs and save boundaries](species-id-architecture.md)

Publish both patches under the hack’s version with distinct filenames such as `yellow-rogue-1.0-vanilla.bps` and `yellow-rogue-1.0-ex.bps`, plus a short choice guide. Record each edition’s settings, accepted input hash, output hash, save format and tested link partners. An edition-specific hotfix should identify the affected edition. A shared release name alone gives players no evidence that saves or link battles can cross editions. The same paired-build workflow can serve a hack that changes only its roster. It requires no roguelike system in PokéRGB’s reference games.
